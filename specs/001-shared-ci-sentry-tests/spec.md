## 1. Problem and intent

- **Problem:** `build.yml` ran `flutter test` on the unpinned stable channel and never `flutter analyze`; there was no
  security scan and no crash reporting; one widget test covered the home hero only; the in-app "Portfolio Mobile App"
  entry linked `github.com/bookchaowalit/bookchaowalit-portfolio-mobile`, which is not this repository.
- **Outcome:** `ci.yml` runs the signing-file guard, analyze and tests on Flutter 3.44.9 for every push and pull
  request, plus the shared security scan. `build.yml` keeps building the store artifacts, now on the same pinned
  Flutter, with the Sentry DSN passed to release builds only. Favorites, project data and Sentry scrubbing are tested.

## 2. Workflow mapping

| Workflow / job | Before | After |
|---|---|---|
| `ci.yml` validate | — | signing guard, `flutter pub get --enforce-lockfile`, `flutter analyze`, `flutter test` |
| `ci.yml` security | — | shared `security.yml` v1.1.1 (`87dc5e1`) |
| `build.yml` build-android | stable channel; release AAB with the Infisical upload key; upload artifact | Flutter 3.44.9; `--dart-define=SENTRY_DSN` on the release AAB; AAB SHA-256 in the job summary. Play upload still only on `v*` tags (unchanged) |
| `build.yml` build-ios | stable channel; unsigned release archive | Flutter 3.44.9; `--dart-define=SENTRY_DSN` on the release build. TestFlight still only on `v*` tags |

The signing-file guard (`scripts/check-signing-files.sh`) stays in both workflows. No signing file is added.
